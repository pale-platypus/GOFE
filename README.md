# GOFE: A General-Purpose, Objective-Driven Feature Engineering Framework

Anonymous code release for the submission *"GOFE: A General-Purpose,
Objective-Driven Feature Engineering Framework"*.

GOFE treats feature engineering as utility-driven optimization: the analyst
plugs in any per-feature, model-agnostic utility measure (mutual information,
|Pearson|, subgroup distance, detector-referenced outlier distance, ...), and
GOFE searches the space of symbolic expressions for features that maximize a
tunable utility–complexity trade-off — without training any downstream model.
The search embeds expression trees with a graph-attention autoencoder and runs
latent-space Bayesian optimization (GP + Expected Improvement).

> Naming note: parts of the code and output paths use the historical internal
> codename `B-MAFE` (and the output tag `mi_gat*`) for what the paper calls
> GOFE. They are the same method; no label in any script refers to an author
> or institution.

## Setup

Python 3.8+. Install dependencies (PyTorch, PyTorch-Geometric and GPyTorch
are required for the encoder and the GP; see the PyG install docs for the
right wheel on your platform):

```bash
pip install -r requirements.txt
```

All experiments were run on a single workstation (8-core CPU, 128 GB RAM, one
RTX 3090). A GPU is recommended but not required. All metric seeds are fixed
(`random_state=0`); GPU training is not bitwise deterministic, so third
decimals of individual cells can vary slightly between re-runs.

## Data

The ten public benchmarks of the paper (UCI / OpenML) ship in `data/`,
together with the exact frozen 70/30 train/test splits used by every held-out
experiment (`<name>__tr.csv` / `<name>__te.csv`, produced once by
`scripts/make_split.py` with a fixed seed, stratified for classification).
Scalability subsamples and million-row synthetic data are regenerated by
`scripts/make_subsamples.py` and `scripts/run_million_scale.sh`.

## Running one GOFE search

```bash
PYTHON=python OUTPUTS_ROOT=./outputs_fair HYPER_CONFIG=default \
NFO_RUN_TAG=gat NFO_EXTRA_OPTS="--num_ops_only" \
bash run_iter.sh pima__tr 0 lsbo 10 mi 1.0
```

Arguments: dataset, CUDA device, method (`lsbo`), search iterations (T=10),
score mode (= plugged-in utility: `mi`, `pearson`, `subgroup_op`, `ifout`,
`downstream`), and the trade-off λ. The selected top-k manifest is written to
`outputs_fair/nfo/RF/lsbo/mi_gat/lam<λ>/<dataset>/selected_topk_lam<λ>.json`.

## Reproducing the paper's results

Each row gives the experiment, the runs it needs, and the script that turns
the runs into the paper artifact.

| Paper artifact | Runs | Table/figure script |
|---|---|---|
| Common-budget quality (Tables 2, 7) | `bash run_quality_compare.sh <ds>` for the ten datasets (all methods, λ ∈ {0, 0.5, 1}) | `python scripts/topk_table.py` (padded top-16, fixed λ=0.5) |
| Held-out utility (Table 3, Fig. 2) | `bash run_fair_all.sh` (every method on each `<ds>__tr` only) | `python scripts/plugin_metric_eval.py --datasets pima german winequality-red airfoil`, then `python scripts/plot_heldout_utility.py` |
| Subgroup purpose (Table 4 top) | GOFE runs with `score_mode=subgroup_op` and `NFO_EXTRA_OPTS="--num_ops_only --subgroup_rule=<r>"` for the top-5 rules on pima, german, winequality-red, spambase | `python scripts/purpose_eval.py --part subgroup_op5` |
| Outlier purpose (Table 4 bottom, histogram figure) | GOFE runs with `score_mode=ifout` at α ∈ {5, 10, 15}% (α selected via `--subgroup_rule`, see `env.py:_ifout_masks`) | `python scripts/purpose_eval.py --part ifout`, then `python scripts/plot_ifout_hist.py` |
| Utility–complexity plane (Fig. "Pareto") | reuses the quality-compare runs | `python scripts/plot_pareto.py` |
| λ trade-off (Table 10, λ figure) | `bash run_lambda_compare.sh` (λ grid {0, 0.2, 0.5, 0.8, 1}) | `python scripts/lambda_retention_table.py`, `python scripts/lambda_simplicity.py` |
| Sensitivity: depth, operators, budget (Table 8, budget figure) | `bash scripts/run_maxorder_ablation.sh`, `bash scripts/run_ops_ablation.sh`, `bash scripts/run_budget_ablation.sh` | `python scripts/depth_table.py`, `python scripts/ops_ablation_table.py`, `python scripts/plot_budget_compare.py pima spambase --stat mean` |
| Scalability (Table 5) | `python scripts/make_subsamples.py`, then `bash scripts/run_scalability.sh amazon 0` and `... spambase 0` (T=3) | `python scripts/plot_scalability_compare.py` |
| Million-scale runtime (Table 11) | `bash scripts/run_million_scale.sh` (synthetic n=20, T=3) | `python scripts/million_scale_report.py` |
| Surrogate accuracy (Appendix B.6) | reuses the fair-protocol runs | `python scripts/purpose_eval.py --part surr` |

Notes on the protocol (matching the paper):

- Held-out evaluations search and select on `<ds>__tr` only; expressions are
  reconstructed on `<ds>__te` and all reported utility is computed there.
- Every method is aggregated over a padded top-16: `scripts/plugin_metric_eval.py`
  pads short methods with seeded draws from a uniform pool of valid random
  expressions over the same grammar (generated once per dataset by
  `run_random.sh`, invoked inside `run_fair_all.sh`; it is the padding-pool
  generator, not a compared method); Cohen's d is capped at 20.
- The subgroup and outlier ground truths (depth-3 tree rules ranked by WRAcc
  with opposite rules, and the frozen train-side IsolationForest at
  contamination α) are constructed in
  `autolearn/feat_selection/nfo/metrics.py`.
- The downstream rerank step enabled in `config/default.json` is a logging
  diagnostic only: it reorders a proposed batch before appending, every valid
  novel candidate is appended regardless of order, and the final top-k
  re-ranks the entire pool by the bi-objective score.
